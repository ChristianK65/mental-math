\section{Introduction}

\subsection{Long-Term Vision}
The long-term vision for the mental math application is to provide a highly personalized, adaptive training experience. The system is structured around independent mathematical domains, each featuring a progressive ladder of calculation patterns.

\begin{itemize}[leftmargin=*]
    \item \textbf{Level-based training}: Each level corresponds to a specific pattern of calculations to master.
    \item \textbf{Domain-specific ladders}: User progress is tracked independently per domain, meaning each domain has its own level ladder.
    \item \textbf{Personalized progression}: Advancement is tailored to the user and evaluated based on:
    \begin{itemize}
        \item \textit{Correctness}: Whether the calculation was solved correctly.
        \item \textit{Speed}: How fast the calculation was solved compared to other users.
    \end{itemize}
    \item \textbf{Comprehensive domains}: The full system will eventually support a wide range of operations, including Addition, Subtraction, Multiplication, Division, Root, Square, and Power.
    \item \textbf{Adjustable difficulty}: Users can manually tune their difficulty level (e.g., warm up, normal, hard).
    \item \textbf{Customizability}: Training configurations will include toggles to allow for negative numbers (minus) and decimals.
\end{itemize}

\subsection{Version 1 Scope \& Constraints}
Version 1 establishes the core mechanics. It is a simplified implementation of the long-term vision with the following constraints:

\begin{itemize}[leftmargin=*]
    \item \textbf{Limited domains}: Only Addition (ADD), Subtraction (SUB), Multiplication (MUL), and Division (DIV) are available.
    \item \textbf{Fixed difficulty parameters}: Difficulty settings (warm up, normal, hard) are disabled. Time cutoffs for correct solves are hard-coded rather than percentile-based.
    \item \textbf{No customizability}: Calculations exclusively feature positive numbers and no decimals.
\end{itemize}

\section{Mechanics for Progression \& Level System}

\subsection{Pattern-Based Levels}

Each domain is divided into ten progressive levels. A \textbf{pattern} specifies the constraints for the questions generated at that level.

\subsubsection*{Generation Rules}
To ensure an appropriate and consistent learning curve, all patterns adhere to the following global rules:
\begin{itemize}[leftmargin=*]
  \item \textbf{Positive Results Only}: Subtraction questions never yield negative numbers.
  \item \textbf{Exact Division}: All division questions result in exact integers, with no remainders.
  \item \textbf{Meaningful Divisions}: Both divisors and quotients are always $\ge 2$ to prevent trivial cases (e.g., $n \div 1$ or $n \div n$).
  \item \textbf{Meaningful Multiplications}: Multiplication operands are always $\ge 2$ to prevent trivial cases (e.g., $n \times 1$).
  \item \textbf{Operand Order Randomization}: For commutative operations (Addition and Multiplication) with differing digit lengths, the display order is randomized (e.g., a 1-digit and 2-digit addition can appear as $17+2$ or $2+17$).
\end{itemize}

\subsubsection*{Progression Tables}
The domain ladders are defined in the tables below based on the following metrics:
\begin{itemize}[leftmargin=*]
  \item \textbf{Level} --- Sequential difficulty step within each domain (1 = easiest).
  \item \textbf{Operands} --- The number of digits per operand (e.g., $2 \times 1$ means a 2-digit number and a 1-digit number).
  \item \textbf{Complexity (Carries / Borrows / Quotient)} --- The operations required to solve the calculation. For Addition, Subtraction, and Multiplication, this refers to the exact number of carries or borrows. For Division, this indicates the number of digits in the resulting \textbf{quotient}.
  \item \textbf{Cutoff (ms)} --- Minimum time budget per question to achieve a ``solved'' status in v1.
\end{itemize}

\subsection{Progression System}

User progression through the levels of a given domain is evaluated based on recent performance. An attempt is considered \textbf{solved} if the correct answer is submitted on the first try and within the level's hard-coded cutoff time $C_L$. Otherwise, the attempt counts as \textbf{unsolved}.

\subsubsection*{Promotion}
To advance from the current level $L$ to $L + 1$, the user must demonstrate consistent mastery. The system evaluates the last $N=5$ completed attempts at Level $L$. Promotion requires that \textbf{all} of the last $N$ attempts are solved. Once this condition is satisfied, Level $L + 1$ is unlocked.

\subsubsection*{Demotion}
To prevent users from being stuck on a level that is too difficult, a demotion rule is enforced based on the last $M=10$ attempts at the current level. A user is demoted if the unsolved rate over these $M$ attempts exceeds a maximum tolerance ($S_{max} = 0.25$ or $25\%$). Demotion is only allowed after a minimum exposure of $M$ attempts at that level.

\textbf{Soft Demotion:} Demotion is intentionally soft. If the user is at level $L$, a demotion moves them to $L-1$ (with a minimum level of $1$). This applies even if the triggering failures happened on a sampled lower-level question $k < L$. For example, if a user at level $10$ repeatedly fails sampled level $8$ questions, their new level is $9$. Formally:
\[
L_{new} = \max(1, L - 1)
\]

\subsection{Level Selection Algorithm}

To balance current level mastery with the review of previous levels and introduction to the next level, the system dynamically samples question levels during play. 
The sampling algorithm heavily weights towards the user's current level, assigns a fixed probability to the next level, and uses a geometrically decaying probability for all lower levels.

\subsubsection*{Symbol Definitions}
\begin{itemize}[leftmargin=*]
    \item $L$: current user level in the domain
    \item $k$: sampled question level ($k \in \{1,2,\dots,L,L+1\}$)
    \item $r$: geometric decay factor for lower levels ($r \in (0,1)$). Smaller $r$ means faster taper.
    \item $u(k)$: unnormalized geometric weight for lower levels
\end{itemize}

\subsubsection*{Sampling Formula}
The base probability mass is statically distributed to the upper levels:
\[
p(L)=0.50, \qquad p(L+1)=0.10
\]
The remaining $0.40$ mass is allocated to all lower levels ($1$ to $L-1$) using a geometric taper so that levels closer to $L$ are more probable:
\[
u(k)=r^{(L-1)-k}, \qquad 1 \le k \le L-1
\]
\[
p(k)=0.40\cdot\frac{u(k)}{\sum_{j=1}^{L-1} u(j)}, \qquad 1 \le k \le L-1
\]
\textbf{Edge Case ($L=1$):} The distribution simplifies to:
\[
p(1)=0.90, \qquad p(2)=0.10
\]

\section{Data Architecture}

\subsection{Question Generation \& Storage}
The system does not hard-code individual questions; rather, it stores generation patterns and derives questions on the fly:
\begin{enumerate}[leftmargin=*]
    \item Store \textbf{Pattern} rows (the generation rules).
    \item Generate question instances on demand using a Random Number Generator (RNG) seed.
    \item Store each user interaction as an \textbf{Attempt} row.
\end{enumerate}
In practice, a ``question'' is represented purely by its identifier pair: \texttt{(patternId, seed)}.

\subsection{Database Schema}
Each pattern family corresponds to a row in the \texttt{pattern} table. Stable, indexed fields are stored as standard columns:
\begin{itemize}[leftmargin=*]
        \item \texttt{id}: unique pattern identifier
        \item \texttt{domain}: defined as \texttt{ADD | MUL | SUB | DIV}
        \item \texttt{level}: ladder level within the domain
        \item \texttt{description}: human-readable pattern label
        \item \texttt{cutoffTimeMs}: solved-time cutoff for v1
        \item \texttt{active}: boolean to enable/disable the pattern
        \item \texttt{createdAt}, \texttt{updatedAt}: audit timestamps
\end{itemize}
In v1, the uniqueness constraint is defined as: \texttt{UNIQUE(domain, level, description)}.
Dynamic generation constraints are stored in a secondary \texttt{params} column (using Prisma \texttt{Json} or PostgreSQL \texttt{JSONB}).

\subsection{Parameter JSON Structures}
In v1, digit fields within \texttt{params} are stored as single integers (rather than lists) because each pattern uses one fixed digit size per side.
